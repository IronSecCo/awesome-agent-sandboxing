# Contributing

Thanks for helping keep this list honest and useful.

## Adding an entry

1. Format: `[Name](link) - one factual sentence.` Sentence ends with a period.
2. Describe what the project **is** and how it isolates code, not marketing claims.
3. Note the license or hosting model (open source / hosted / both) where relevant.
4. Put the entry in the section that best matches its isolation mechanism.
5. Keep the list alphabetical-ish within a section only where it already is; otherwise group by relevance.

## What we accept

- Tools and platforms that sandbox or isolate untrusted or agent-generated code.
- Isolation technologies (kernel, microVM, WebAssembly, language-level) used to build such sandboxes.
- High-signal learning resources and reproducible benchmarks.

## What we do not accept

- Entries that assert third-party capabilities that cannot be verified. Link to the project's own docs instead.
- Dead links, abandoned projects with no isolation angle, or pure marketing pages.
- Duplicate entries. Search first.

## Process

Open a pull request editing `README.md`, or open an issue proposing an entry. Maintainers
review for accuracy and fit. Affiliation with any listed project (including IronClaw) does
not grant or block inclusion; merit does.
